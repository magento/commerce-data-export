# AdobeCommerce_ProductReviewSummaryAttributes

Adds the product review summary to the Catalog Service products feed as two system product attributes:

| Attribute code      | Label            | Value                                        | Type                        |
|---------------------|------------------|----------------------------------------------|-----------------------------|
| `ac_review_count`   | Review Count     | Number of approved reviews                   | Number (`numeric`, decimal) |
| `ac_rating_summary` | Average Rating % | Average rating as a percentage (`0` - `100`) | Number (`numeric`, decimal) |

The attribute codes are a public contract shared with Catalog Service and the storefront and must not be renamed.
Both attributes use the Number input type from `AdobeCommerce_CatalogProductNumericAttribute`, so they are exported with
`numeric: true` and can be used for range facets and sorting.

## Review summary source

Values are provided by `AdobeCommerce\ProductReviewSummaryAttributes\Api\ReviewSummarySourceInterface`.

- `isEnabled()` - whether review summaries are exported.
- `getSummaries($productIds, $storeViewCodes)` - summaries keyed by `ReviewAttributeContract::key($productId, $storeViewCode)`,
  with `reviewCount` and `ratingSummary`. Products without a summary are omitted.

The default preference, `Model\Source\DisabledReviewSummarySource`, is disabled and returns nothing. A review provider
module enables the feature by overriding the preference, e.g.:

```xml
<preference for="AdobeCommerce\ProductReviewSummaryAttributes\Api\ReviewSummarySourceInterface"
            type="Vendor\Module\Model\ReviewSummarySource"/>
```

A source is also responsible for scheduling a products feed resync when review summaries change.

## Behavior

- **Disabled source (default)**: no attributes are created and the feeds are unchanged.
- **Attribute creation**: attributes are created during the products feed sync, only when at least one exported product
  has approved reviews. They are not added to the shared `SystemAttributeRegistrar` configuration, which creates
  attributes for every merchant.
- **Values**: added at export time only to products that have a review summary. A summary with 0 approved reviews is
  exported as `0`, so values are updated when reviews are unapproved or deleted. Values are never read from EAV, so
  saving a product cannot overwrite them.
- **Attributes created by merchants**: if a merchant already created an attribute with one of these codes (user defined,
  or with a different type), it is not treated as a review summary attribute: no values or overrides are exported to
  it, it is not changed on save, and `CDE01-26` is logged.
- **Storefront properties**: the PDP role (`visible` in the product attributes feed) is always on. Listing, search,
  sort and filter properties are disabled by default and can be enabled by merchants in Stores > Attributes > Product.

## Admin

- The attributes are system attributes (`is_user_defined = 0`) and cannot be deleted.
- They are listed in Stores > Attributes > Product with a notice that they are generated by the system.
- They are removed from the product edit form (`attributesToEliminate` of the product form EAV modifier) and from the
  Update attributes mass action.
- "Values Required" is locked on the attribute edit page and forced to `No` on every save, since a required
  attribute without a value on the product edit form would block product saves.
